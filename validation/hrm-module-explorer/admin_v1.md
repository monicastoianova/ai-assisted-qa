## Purpose

The Admin module is the system configuration and governance center of OrangeHRM. It controls who can log into the system and what they can do (user accounts and roles), the reference data that the rest of the application depends on (job titles, pay grades, employment statuses, locations, qualifications), the company's organizational structure, and system-wide technical settings (email delivery, localization, enabled modules, authentication methods). Every other module in OrangeHRM (PIM, Leave, Time, Recruitment, Performance) draws its dropdown values and permission model from data configured here.

## Business Context

HR administrators and IT/system administrators are the primary users of this module. In day-to-day operation:
- **HR/People Ops** maintains job-related reference data (Job Titles, Pay Grades, Employment Status, Job Categories) so that these values appear consistently across employee records, recruitment postings, and reports.
- **HR/Org design** keeps the company's Locations and Organization Structure current as the business grows, adds offices, or reorganizes sub-units.
- **System Administrators** manage System Users (creating/disabling logins, assigning roles), configure outbound email so the system can send notifications (leave approvals, password resets), and control which application modules are active for the whole instance.
- **IT/Security** configures LDAP and OAuth/social-media authentication for centralized login, and applies corporate branding (logo, colors, banners) to align the instance with the company's identity.

Because this module underpins the reference data used everywhere else, changes here (e.g., disabling a module, deleting a job title, changing a user's role) can have wide-reaching downstream effects.

## Relationships to Other Modules

- **PIM**: Job Titles, Pay Grades, Employment Status, Job Categories, Nationalities, Skills, Education, Licenses, Languages, and Memberships all populate dropdowns/fields on employee records in PIM.
- **System Users**: Each system user account is linked to an employee record (typically created via PIM) and assigned a User Role that governs module access instance-wide.
- **Leave / Time / Recruitment / Performance / Directory / Maintenance / Claim / Buzz**: All can be globally enabled/disabled via Configuration → Modules; their visibility in the sidebar depends on this setting.
- **Leave**: Email Subscriptions' 5 notification types are all Leave-specific, showing Admin's tight coupling to Leave workflow notifications.
- **Organization Structure/Locations**: Referenced by PIM's employee assignment (sub-unit, location) and by Recruitment postings.
