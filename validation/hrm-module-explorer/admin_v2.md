# OrangeHRM — Admin Module

> Auto-generated by the `hrm-module-explorer` skill on 2026-07-13

## Purpose
The Admin module is the system-configuration center of OrangeHRM. It lets an HR/IT administrator manage who can access the system (system users and roles), define the shared reference data other modules depend on (job titles, pay grades, employment statuses, work shifts, locations, org structure, skills/education/licenses/languages/memberships, nationalities), and configure system-wide behavior (branding, email/SMTP, localization, language packs, module visibility, and authentication integrations such as social login, OAuth clients, and LDAP).

## Business Context
IT/HR administrators use this module during initial setup and ongoing maintenance: onboarding new admin/ESS users, keeping job- and org-related picklists current for PIM/Recruitment/Performance, applying corporate branding to the login/dashboard experience, and wiring up authentication (LDAP/SSO/OAuth) so the company's identity systems integrate with OrangeHRM. Most submodules are simple reference-data managers (Add/Edit/Delete lists) that feed dropdowns used elsewhere in the app (e.g., Job Title and Pay Grade appear on PIM job details; Employment Status and Work Shifts appear on employee records).

### LDAP Configuration
**What it does:** Configures integration with an external LDAP directory for authentication and user provisioning, including field mapping between LDAP attributes and OrangeHRM user fields.
**Who uses it:** System/IT administrators integrating with corporate directory services.
**Key fields / actions:**
- "Enable" toggle for the whole feature.
- Server Settings: Host* (default `localhost`), Port* (default `389`), Encryption dropdown, LDAP Implementation dropdown.
- Bind Settings: "Bind Anonymously" toggle (checked by default).
- User Lookup Settings: Base Distinguished Name*, Search Scope dropdown, User Name Attribute* (default `cn`), User Search Filter* (default `objectClass=person`), User Unique ID Attribute.
- Data Mapping: per-field LDAP attribute mapping for First Name* (default `givenName`), Middle Name, Last Name* (default `sn`), User Status, Work Email, Employee Id — each with a checkbox to use that field as the employee/user mapping key.
- Additional Settings: "Merge LDAP Users With Existing System Users" toggle, Sync Interval (in Hours)* (default `1`).
- Warning banner recommending a database backup before activating LDAP.
- Buttons: Test Connection, Save.

## Relationships to Other Modules
- Job Titles, Pay Grades, Employment Status, and Work Shifts populate dropdowns on PIM employee job-details records.
- Skills, Education, Licenses, Languages, and Memberships populate the Qualifications tab on PIM employee records.
- Locations and Organization Structure feed the org-unit/location assignment fields used in PIM and Recruitment.
- Nationalities populates the Personal Details tab on PIM employee records.
- Modules configuration directly controls which top-level modules (Leave, Time, Recruitment, Performance, Directory, Maintenance, Claim, Buzz, Mobile) are visible/usable system-wide.
- Email Subscriptions and Email Configuration govern notification delivery for Leave-module events.
- LDAP Configuration, Social Media Authentication, and Register OAuth Client govern how users authenticate into the whole system, including PIM/ESS logins.
